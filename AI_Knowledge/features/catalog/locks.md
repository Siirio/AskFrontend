# Catalog — Slice Locks

LOCKED | Product Card is ONE component with ONE presentation — a modal only | D33 (2026-08-06, supersedes D10): no full-page presentation exists or will be built. `/app/product/:id` is a permanent informational stub, not a second copy of the card | src/catalog/ui/ProductCard*, src/app/app/(main)/product/[id]/page.tsx
LOCKED | The seller Products tab lives in catalog/, not business-cabinet/ | The slice that owns the data owns the feature; the cabinet only composes it (D8, §3) | src/catalog/ui/*, src/business-cabinet
LOCKED | Never invent stock, delivery, logistics, or availability | It must come from supplier input or trusted integration data — a backend lock | ProductCard, product forms
LOCKED | One concrete sellable variation = one product; no client-side variant grouping | No variant tables exist. Grouping is a backend concern via tags | src/catalog/model.ts
LOCKED | Every product form includes branch selection | Price and availability are branch-level (M2M) — a product without a branch is not sellable | product create/edit forms
LOCKED | Import is preview-then-approve — never a silent one-click commit | The seller must see valid/warning/invalid rows before products go live | import wizard
LOCKED | No chat button, and no zero-destination chat fallback, until `@/chats` ships (slice #4) | `@/chats` has no `index.ts` yet (R2 — cross-slice imports only through the door); a reachable control that goes nowhere is forbidden (project lock). Added 2026-08-06 while building the Product Card modal, so the next session does not re-stub a disabled button or re-derive this from memory | src/catalog/ui/PurchaseAction.tsx
LOCKED | `catalog/model.ts` types are OWN copies of the relevant `SearchCardResponse` fields, never imported from `@/search` | `search/ui/ResultStream.tsx` imports `ProductCardModal` from `@/catalog` — importing a type back from `@/search` would close a cycle between the two slices, which R5 forbids ("if two slices need each other... the boundary is wrong"). A `SearchCardResponse` value passed into a `ProductCardData`-typed prop still type-checks structurally; the duplication costs nothing at runtime. Added 2026-08-06 | src/catalog/model.ts
