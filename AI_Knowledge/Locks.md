# ASK Frontend — Project Locks

Format: `LOCKED | {what} | {why} | {scope}`

Breaking requires: (1) explicit user approval, (2) proof surrounding extension is insufficient.

## Structure Locks
LOCKED | Slices mirror AskBackend module names; a feature folder exists per slice, 1:1 | One mental map across the product; 1:1 mapping if backend modules ever become services | src/*, AI_Knowledge/features/*
LOCKED | No layer folders — entities/, features/, widgets/, or global components/services/utils | Code is cut by domain, not by technical layer (VSA) | src/ top level, boundaries/no-unknown-files + boundaries/no-unknown-dependencies
LOCKED | Cross-slice imports only through the slice's index.ts | The door rule (R2) — deep imports couple internals and freeze them | boundaries/dependencies (fileInternalPath "index.ts" policy)
LOCKED | shared/, design-system/, lib/ never import a slice or app/ | One-way dependency (R1) — the toolbox knows nothing about the business | boundaries/dependencies
LOCKED | No business words in shared/ — translations are the one sanctioned exception | Domain-aware code belongs to its slice (§5 litmus test) | src/shared/*
LOCKED | ESLint boundary rules are never disabled or weakened to make a change pass | Boundaries are compile-time laws, not conventions | eslint.config.mjs, the npm run build chain

## Rendering & State Locks
LOCKED | Route files and layouts stay server components; 'use client' only at interactive components | Public surfaces must server-render — SEO is a core requirement (D7) | src/app/**/page.tsx, layout.tsx
LOCKED | zustand stores are factories consumed via context providers, never module-scope singletons | Module-scope stores leak state across SSR requests | slice store.ts
LOCKED | api.ts / model.ts / store.ts stay free of DOM and browser APIs | They run server-side during SSR now, and lift into React Native packages later (D5) | slice api.ts, model.ts, store.ts

## Data Locks
LOCKED | Components never call fetch or an endpoint URL — only the owning slice's api.ts | Single HTTP implementation; one place to change a contract (§7, P1.2) | all ui/ components
LOCKED | Token access only through shared/api storage helpers; ask.accessToken is the storage key | Cross-app contract + swappable TokenStorage for mobile (P5.2, D6) | shared/api, auth slice
LOCKED | The backend is the data authority — DTO shapes are never invented or patched client-side | A mismatch is raised, never silently faked (P9.4) | slice api.ts, model.ts

## Product Locks
LOCKED | Build only screens, flows and controls that exist in PRODUCT_VISION.md | The vision is the product authority (D9, P9.1). Invented UI is forbidden — if it seems missing, STOP and ASK | all ui/, app/(marketing). **NO exemptions as of 2026-08-01 (D31)** — the single one that existed (`src/app/demo/page.tsx`, the design lab) went away with the lab. Every surface in the repo must now exist in the vision on its own account
LOCKED | The neumorphic skin is applied in exactly ONE place — the `neu-skin` wrapper in `app/app/layout.tsx` — and never on `:root` | Placement IS status again: everything inside the platform shell is neumorphic by construction, and the marketing landing cannot become neumorphic by accident. Putting the palette on `:root` to "fix" a portaled surface would silently reskin the landing; portals are pointed back INSIDE the scope instead (see the portal lock below) | src/app/app/layout.tsx, design-system/neumorphism.css
LOCKED | Every Radix-portaled surface (Dialog, DropdownMenu, Select, and any new one) MUST pass `container={useSkinPortalContainer()}` | A portal defaults into `<body>`, OUTSIDE `neu-skin`, where a colour utility silently resolves to the MARKETING palette and every `.neu-*` class silently matches nothing. Both failures are invisible in code review and in a diff — they only show in a browser, and they shipped once: the role modal's cards and its Continue button rendered with no shadow and no fill (caught 2026-07-27 by driving the screen, not by reading it). The first fix re-declared the variables on the portal node and did not scale — once the `.neu-*` rules must work out there too, "a handful of variables" becomes the whole palette in triplicate | src/shared/ui/skin-portal.ts, src/shared/ui/{dialog,dropdown-menu,select}.tsx
LOCKED | `#ask-skin-root` (the `neu-skin` wrapper) never carries a transform, filter or perspective | Any of the three makes it a containing block, and every `position: fixed` overlay in the product — now portaled INSIDE it — silently re-anchors to the wrapper instead of the viewport | src/app/app/layout.tsx, design-system/neumorphism.css
LOCKED | Marketing content lives only in app/(marketing)/ — content only, never imports a slice | One copy of the marketing content; the landing stays static and SEO-first (D6) | src/app/(marketing)
LOCKED | The /app/* prefix and the marketing / route are kept | Preserves the future app. subdomain split without breaking a single URL (D6) | src/app/app/*
LOCKED | Everything under the (main) route group is auth-gated; /app/auth/* is the ONLY logged-out-reachable /app subtree; legal/public pages (terms, privacy, cookies) live OUTSIDE /app | Owner rules 2–3 (D23): the (main)-group boundary is the gate line, so a new authenticated page is protected by placement alone — putting a public page under (main) silently gates it, putting a gated page outside it silently exposes it | src/app/app/(main)/*, src/app/(marketing)/{terms,privacy,cookies}
LOCKED | A guard's scope is narrowed with a route GROUP, never a per-URL allowlist inside the guard | D26 (2026-07-27). `RequireDashboardAccess` sat at `business/layout.tsx` and so covered `/app/business/*` entirely — correct until seller REGISTRATION had to live under that prefix, reachable by the customer the guard exists to bounce. The fix keeps the D23 grammar instead of adding an exception to it: `business/(cabinet)/` carries the guard, `business/register/` is the one sibling outside it. An allowlist would have moved the access rule from the file tree into a conditional, where the next page silently inherits nothing | src/app/app/(main)/business/(cabinet)/layout.tsx, src/app/app/(main)/business/register/
LOCKED | A control that is reachable must DO something — a route that a guard immediately bounces is a bug, not a placeholder | The role modal's "set up your business" shipped pointing at `/app/business`, where the guard sent the fresh customer straight back: a live-looking fork that silently did nothing for weeks, invisible in review because both halves were individually correct. If the destination does not exist yet, the honest options are to build it, to say plainly that it is not open, or to not offer the control — never to point it somewhere that swallows the click | all ui/, src/auth/ui/RoleSelectionModal.tsx
LOCKED | `RequireDashboardAccess` bounces a customer-only session to `/app/business/register`, never to `/app` | D27 (2026-07-28). Applies the D26-era "reachable must DO something" rule to the bounce itself, not just the destination page: sending a would-be seller to Home instead of the registration door left them with no next step, even though `business/register/` already existed as the guard's own sibling route for exactly this visitor | src/auth/ui/RequireDashboardAccess.tsx
LOCKED | An e2e stub for a backend endpoint is written from the JAVA DTO, never from our own model.ts | 2026-07-27: the suite was green for weeks while sign-up 400'd in production, because the stubs answered with `auth_challenge_id` — the name WE used — after the backend renamed it `verification_id`. A stub built from the client's assumption can only prove the client agrees with itself; it tests nothing about the contract it claims to cover | e2e/*.spec.ts stub bodies
LOCKED | No magic visual values — colors, sizes, spacing, radii come from design-system/ | One visual source (D3, P9.2). D25 did not weaken this: the neumorphic shape/depth values live in `design-system/neumorphism.css` as `.neu-*` classes, NOT inline in components, precisely because `@theme inline` cannot express them as tokens. "It could not be a token" is not licence to put a px literal in a component | all ui/, design-system/*.css, tailwind theme
LOCKED | shadcn-generated code is copied and restyled to design-system tokens before first use — Radix supplies behavior only, never a shipped default value | shadcn is scaffolding, not a live design source (D12); P9.2 applies without exception | src/shared/ui/*
LOCKED | GSAP animates transform/opacity only — never width/height/top/left | Layout-triggering properties force a recalculation every frame; this is what keeps motion smooth (D11) | shared/motion.ts, all GSAP usage

## Design Locks
The visual direction was decided by the product owners. These are its invariants — an agent may improve the EXECUTION, never re-open the DECISION. Full operational rules: `.claude/skills/{marketing,platform}-ui-design/SKILL.md`.

LOCKED | No marketplace idioms, anywhere: no star ratings / review scores / 5-point scales, no buy-box, no cart or checkout, no visible match score, and never a price-first default sort | ASK is an intent layer that routes demand to brands WITHOUT commoditizing them. The marketplace is the pattern the training data reaches for by default, so this must be a law, not a preference | all ui/, app/(marketing)
LOCKED | ONE accent and it is ORANGE, on warm neutrals | Result cards stage many businesses' own logos and brand colors at once; a second ASK hue fights them. The orange must pass WCAG AA on light AND dark with a STATED foreground, and must not collide with the offer/discount label | design-system/, all ui/
LOCKED | Trust badges (data freshness, confirmation speed, card quality, business activity) render as METADATA — never a score, never a green/amber/red traffic light, never anything mistakable for a rating | They are facts about a listing, not opinions about a business. A score is a rating by another name, and this product has no ratings | all ui/ badges
LOCKED | TINT IS INFORMATION. A Unique Offer is a low-chroma tint with ink text and bold tabular numerals — never an accent fill, never a pill | Solves the discount collision (D13): if orange is BOTH the primary action AND the sale signal they compete, and ASK starts looking like the marketplace it refuses to be. The separation is by register, not hue — so it survives a palette change, and it survived the D25 reskin unchanged | design-system/neumorphism.css, all ui/
LOCKED | Every colour pair the product renders is MEASURED, and the measurement is written down beside the values | Not a style rule — the only thing standing between a redesign and an unreadable product. The /demo port (D24) was never measured and carried three AA failures into D25, caught only because this lock forced the computation at promotion time. A contrast claim that was not computed is not a claim. **ENFORCED since 2026-08-01 for `tokens.css`** — `scripts/check-tokens.mjs`, a mandatory stage of `npm run build`, recomputes every documented ratio and fails the build when the table, the floors, the gamut or the two dark blocks disagree (architecture §8 note). `neumorphism.css`'s table is NOT yet covered: its values are hex, not OKLCH, so the same parser does not reach them — measure it by hand until that is closed | design-system/*.css verification tables, scripts/check-tokens.mjs
LOCKED | The webfont MUST load the `latin-ext` subset — ₸ (U+20B8) lives there, in NO Cyrillic range | A ru/kk product naturally loads only cyrillic+cyrillic-ext; that silently falls every price on the platform back to a system font. Verified, not assumed (D13) | src/app/layout.tsx
