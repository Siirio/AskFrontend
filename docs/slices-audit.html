What's actually worth doing next

ranked by what's blocking, not by file count
Live consent gap

Legal acceptance is written but never read back. The backend shipped pendingLegalDocuments + session gating on 2026-08-03. The frontend still only fires the registration-time write — nobody is blocked from the app if a write silently fails, which is exactly the failure mode the gate exists to close.

Biggest single gap

Three of seven slices have zero code. chats, profile, services are placeholder routes only. catalog moved to partial 2026-08-06 — customer half shipped, seller half still zero code. Backend support for all three is already mature — this is pure frontend backlog, not a cross-repo block.

Resolved since last read

G1 and G3 are fully closed and consumed. Deep paging, company filter, map-area, unique-offer sort, and ordered purchase destinations all shipped backend-side 2026-08-03/04 and are live in search as of 2026-08-05. No outstanding backend ask blocks any customer-path slice today.

Open, non-blocking

Gate G2 — Company Profile scope has no backend endpoints and the vision itself says "coming in a future update." Ship the placeholder when the cabinet tab is built; don't invent a screen.
